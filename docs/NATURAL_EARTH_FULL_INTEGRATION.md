# Natural Earth offline data, raster maps, and Geographic Region

**Status:** experimental OpenFX integration on the PR #3 development branch.
The **215/215** audit applies to official pinned vector source datasets only.
It does not imply that the separately inventoried raster variants were all
downloaded, converted, or rendered successfully. A full-data release remains
blocked until the full publisher dataset and the actual Resolve host pass.

## Architecture

- The runtime is C++17 OpenFX with **no network calls, GDAL or Python**.
- The release machine may use Python, SQLite, and the explicitly pinned
  **Pillow** dependency to convert publisher imagery. Original TIFF/TFW
  georeferencing is validated; rotation and off-EPSG:4326 bounds are rejected.
- Rasters are converted to **equirectangular 256×256 straight RGBA tiles** at
  source native resolution and progressively downsampled resolution levels.
  Runtime chooses an appropriate resolution from camera zoom, reads bounded
  local tiles and composites via the existing OFX byte/float pixel system.
- Raw Natural Earth raster families have **10m and 50m** scales; there are no
  official 110m raster families. The 52 discovered download variants are
  distinct source links, not necessarily 52 distinct independent layer themes.
- Full archive SHA256/ZIP CRC validation is performed **before** raster
  ingestion, and a separate SHA256-per-file manifest is verified by the
  installer. File paths are constrained to the offline data root.
- GeoPackage region search uses SQLite FTS5 with a read-only index. Country,
  state and city selections keep publisher table/row references; continent
  selections combine **real country polygons** grouped by publisher continent
  name, not fictional administrative boundaries.
- Region appearance is stored in the Resolve clip's persisted
  `GeographicRegionSaved` property, as a bounded list of 64 independent
  RGBA selections, keyed by stable feature IDs.

## Build the full offline data pack (release machine only)

Prepare separately:

1. The published `natural_earth_vector.gpkg` (182 aggregate tables).
2. The verified 33-layer supplemental GeoPackage generated by
   `tools.natural_earth.supplements`.
3. The official `official_sources.json` created by `inventory.py` and the
   matching SHA256-verified `source-archives.json` from `materialize.py`.
   The publisher releases more source links than there are unique themes;
   archive integrity and full geographic layer coverage are checked
   independently. Downloads are allowed only on the release machine.

Then run:

```bash
python -m pip install Pillow==11.3.0

python -m tools.natural_earth.assemble_pack \
  --vector /publisher/natural_earth_vector.gpkg \
  --supplement /publisher/supplements.gpkg \
  --sources /publisher/official_sources.json \
  --archives /publisher/downloads/source-archives.json \
  --archive-root /publisher/downloads \
  --vector-pin data/natural-earth/vector_layers_v5.1.2.json \
  --supplement-pin data/natural-earth/aggregate_geojson_supplements_v5.1.2.json \
  --out /release/CartoRigNaturalEarth
```

This command validates the archives, builds the SQLite search index, prepares
every inventoried raster source, verifies the 215 vectors including the 33
supplements, evaluates raster coverage, and constructs the deterministic
`pack.json` manifest. It fails and does not publish the output directory
unless **all** requirements pass.

The only non-certified option is `--allow-incomplete`, which creates
`status: EXPERIMENTAL_INCOMPLETE`. This is intended for developer fixtures,
never a complete Natural Earth release. Neither raw downloads nor generated
gigabytes of tiles are committed into Git.

### Offline Windows install

Copy the whole prepared data directory to the customer computer by USB,
offline drive or another **non-runtime** delivery method. In PowerShell:

```powershell
.\Install-CartoRigNaturalEarth-DataPack.ps1 `
  -SourceRoot "D:\CartoRigNaturalEarth" `
  -Confirm:$false
```

By default, installation targets:

```text
%LOCALAPPDATA%\CartoRigNative\NaturalEarth
```

Installer behavior: verify SHA256 and byte count of each source file, copy to
staging on the destination disk, verify staging again, atomically move previous
data to backup, move staging to live, and roll back if anything fails.
Close Resolve before installing/upgrading the data pack. Use `-Upgrade` to
replace a previous installed pack. Use `-AllowIncomplete` only for
explicit experimental test packs; a normal install rejects incomplete packs.

## DaVinci Resolve 20 Edit-first Inspector

After installing the OFX plugin and the offline data pack, set:

| Inspector control | Installed file/location |
| --- | --- |
| Vector GeoPackage | `...\NaturalEarth\vector\natural_earth_vector.gpkg` |
| Additional layer GeoPackage (optional) | `...\NaturalEarth\vector\supplements.gpkg` |
| Offline search index | `...\NaturalEarth\vector\catalog.sqlite` |
| Raster tiles directory (offline) | `...\NaturalEarth\raster` |
| Raster asset ID | See the `asset_id` field in `raster/validated-raster-assets.json` |

Blank raster asset and blank additional vector layer retain their previous
default behavior. There is no external raster URL, API key, or tile service.

### One-click installed offline data pack

The new **Use installed offline Natural Earth data pack** toggle is OFF by
default, so installing the pack does not alter previously authored maps.
When enabled, an otherwise blank Vector GeoPackage, additional layer
GeoPackage, search index and raster tiles directory resolve from:

```text
%LOCALAPPDATA%\\CartoRigNative\\NaturalEarth
```

An alternative pack root can be set before launching Resolve via the
`CARTORIG_NATURAL_EARTH_PACK` environment variable. Explicit Inspector file
paths always take priority. A missing installed pack or required file fails
with an actionable error; there is **never a network fallback**.

### Search offline raster

The raster picker uses only `raster/validated-raster-assets.json` plus the
existing local asset `index.json` files:

1. Enable the installed pack toggle, or set **Raster tiles directory (offline)**.
2. Enter a source identifier or part of its name in **Search offline raster**.
3. Choose a matching entry in **Offline raster results** (the first ten
   matching assets, ordered by source ID).
4. Click **Use selected offline raster**. The chosen atlas ID is saved with
   the clip in **Raster asset ID**. Selecting **No raster selected** and
   applying disables imagery without clearing the vector or regional styling.

The picker does not download anything, generate geographic data, or silently
accept unverified entries. Dynamic dropdown labels are confirmed with a
synthetic OpenFX host but still require **real Resolve 20 host acceptance**.

The native raster cache now retains at most 64 RGBA tiles (16 MiB) per render.
Previously a wide view could fail after loading too many distinct tiles.
A 65-tile stress fixture validates eviction, repeatable output, and rejection
of corrupted source tiles. This is memory bounded, not a guarantee of 8K
interactive frame rates.

### Geographic region

Open **Geographic region** in the Inspector:

1. Choose **Continent**, **Country**, **State / Province**, or **City**.
2. Type a name in **Search location**. Search is accent-tolerant and offline.
3. Review the matching source names in **Matches / selected**; for ambiguous
   names choose the matching **Search result** ordinal, 1–10.
4. Set independent **Region red / green / blue / opacity** controls.
5. Click **Add / update selected region**. Selecting the same feature and
   clicking again replaces *only that feature's* color.
6. To animate a region, choose it under **Selected region to animate / edit**
   and position the Resolve playhead. Choose **Smoothstep**, **Linear**, or
   **Hold**, edit the RGBA controls, then click **Capture RGBA key at playhead**.
   Repeat at another frame. Each selection maintains its own bounded,
   persistent 64-key timeline, evaluated on `SceneTimeOffset/SceneTimeScale`.
7. To delete a region, click **Remove saved region** for the selected
   persistent item; **Remove matching search result** remains an alternative.
   The persistent selected-region JSON stays with the clip/project; it is not
   written to a global settings file.

City entries in Natural Earth are **point features** and are rendered as such,
not as invented municipality borders. A derived continent uses published
admin-0 country polygons. Source geometries remain 4326.

### Current usability limitations

- Result names in the Inspector label rely on the host accepting an OpenFX
  `InstanceChanged` label update. The stored selected feature IDs and styles
  are host-agnostic, but dynamic label and dropdown refresh are **not yet
  confirmed in DaVinci Resolve Studio 20**. Capture buttons also require
  host acceptance of the `kOfxPropTime` passed to `InstanceChanged`; when
  the host supplies no playhead time, a capture uses the default time zero.
- The Inspector exposes a result ordinal rather than a genuinely dynamic
  dropdown of arbitrary location names; there is no click-to-select-in-Viewer
  or per-region native bezier keyframing yet.
- All region source paths refer to external local data; moving a .drp project
  to another machine requires installing the same offline pack or relinking
  those paths. Clip-persistent JSON by itself is not an embedded data pack.
- The raster renderer currently uses source-resolution-appropriate nearest
  sampling without advanced texture filters, region masks or GPU acceleration;
  4K/8K interaction and multicamera performance still require profiling.
- Very large vector layers are limited to 20,000 features/2 million vertices
  when selected as a single optional overlay, until viewport streaming is
  implemented. The 215/215 *source inventory* gate is not a claim that all
  those tables currently render as one bounded layer.
- PSD publisher raster variants are imported from their raster composite.
  Editable Photoshop layer semantics are not exposed as independently
  stylable layers inside Resolve.
